编写与审核

组织方式

目录使用中文，不加编号。一个类目或一个加热系统先维护一个主页面，资料放在相关章节中；避免为尚无内容的子类目提前拆文件。跨类目内容选择一个主归属，通过相对链接引用。

编写与审核

  • 关键结论提供原论文、机构资料或可追溯内部报告，注明版本、日期与原文位置。
  • 数值包含单位、工况和误差；区分设计目标、仿真预测、实验测量与待验证假设。
  • 未完成内容标注“待补充”；只有实际完成领域审核后才标记“已审核”。
  • 文献更新时同时维护 来源索引。网页访问日期与论文发表日期分别记录。
  • 仿真保存代码版本、输入、网格、时间步及守恒检查；实验保存标定、原始数据入口与不确定性。

正文写法

直接解释概念、推导和结果。公式旁注明所需假设、符号及单位；算例给出输入、计算步骤、结果和物理解释。参考文献定位到相关章节、公式或图表。

引入公式时，写明从哪个定义、守恒方程或近似出发，列出得到结果的关键中间步骤，再给数值代入。经验拟合式应交代拟合变量、单位与数据范围；不要为经验系数编造理论推导。引用其他专题已推导的关系时，链接到对应正文。

专题按自身的物理与工程问题组织。辅助加热各系统使用具体技术标题，不统一套用“测试与验收”“文献与案例”作为收尾；测量方法、装置证据和参考资料放到它们所支持的论述附近。

避免反复插入免责声明、防御式对比和空泛提醒。用具体模型条件表达适用范围，审核状态与检查结果集中记录在页面标记和核验记录中。资料目录、术语和项目档案类条目采用阅读、换算或比较实例，按内容需要使用公式。

通用记录信息

标题、归属类目、装置、加热系统、标签、负责人、更新时间、来源和审核记录。

审核状态：草稿、审核中、已审核、已归档。证据类型：资料摘要、解析计算、数值仿真、实验观测、工程测试、待验证假设。来源类型与审核状态分别记录。

文件与资料

Markdown 保存知识正文。较大的 CAD、波形、视频与原始数据存放在团队资料库，在正文记录位置、版本和校验值。根据已有使用权决定是否收录外部全文；本仓库不默认授予开源许可。

更新流程

  • 在相关页面补充内容，通过拉取请求说明变化、来源、验证范围及审核需求。
  • 提交前运行 python3 工具/检查知识库.py，检查目录结构与本地链接。
  • 本地结构检查不代替原始资料核验或技术评审。
