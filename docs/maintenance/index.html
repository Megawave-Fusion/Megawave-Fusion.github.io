网站维护

在线站点：Fusion Stacks。源仓库：Megawave-Fusion.github.io。

源文件与阅读结构

各中文目录的 README.md 是知识正文。site/site.json 登记章节和专题，site/tags.json 登记条目永久标签。每个专题的二级标题生成独立条目，正文也完整显示在专题连续阅读页。

目录中，只有一个专题的章节直接进入连续正文；多专题章节保留可展开的专题列表。顶栏统一放目录、知识树、文献和讨论，正文侧栏只用于切换章节，编写与版本信息集中在页脚。阅读翻页保留在正文末尾，引用和编辑工具按需展开。旧章节地址与永久条目地址继续有效。

原仓库的 Git 历史随项目迁移，原有 18 份 Markdown 文档、来源记录和六套独立加热系统均保留。网站维护文档属于新增的站点说明。

条目默认是草稿，不因构建或部署成功而自动变为“已审核”。编写规范见 编写与审核。

本地构建

使用 Python 3.10 或更新版本。首次准备环境：

python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt

MathJax 3.2.2 已随源码收录，不依赖外部 CDN。若从不含 vendor 的源包开始，可运行 .venv/bin/python scripts/vendor_mathjax.py 从官方 npm 包恢复。

普通修改后：

.venv/bin/python 工具/检查知识库.py
.venv/bin/python scripts/build.py
.venv/bin/python scripts/check_site.py _site
.venv/bin/python -m http.server 8000 --directory _site

浏览器访问 http://localhost:8000/。修改脚本后可运行 node --test tests/search.test.mjs 检查中文、缩写、标签和章节筛选。

永久标签

新增二级标题时运行 .venv/bin/python scripts/build.py --register-tags，检查并提交 site/tags.json 的新增记录。标签如 MF000001 与章节显示编号分离。

改标题或移动源文件时，先在登记表中修改对应键，保留原 tag。构建遇到消失的登记项会失败，防止旧链接被静默废弃。删除或合并条目前需安排旧标签的明确去向。

知识树的数据与关系

知识树提供三维神经网络和学习流程图两种视图。两种视图使用同一组永久条目；最小的条目节点与 MF 标签和条目页一一对应。三维视图以真实的 x、y、z 坐标和 WebGL 渲染，支持旋转观察、平移和缩放；按“聚变知识库 → 章节 → 专题 → Tag 条目”组织四级大小节点，各级可展开与折叠，并可进入相应目录或正文。当前对应 1 个根节点、10 个章节、23 个专题与 163 个条目，共 197 个节点。层级归属连线与条目之间的学习关系分别显示，学习路径用于选择建议的阅读顺序；三维位置及视觉距离不表示新的物理关系或学习先后。

scripts/knowledge_graph.py 从登记正文生成标题、摘要、章节、专题、审核状态和永久链接。摘要摘自现有正文；公式以“公式见正文”提示代替，以免在图中显示原始 TeX。构建产物为 /data/knowledge-graph.json，不需要手动维护另一套条目清单。

site/knowledge-relations.json 单独维护编者挑选的关系与学习路径。prerequisite 从建议先读条目指向后读条目；它是教学编排建议，不表示严格、唯一或完整的科学依赖。related 表示无向主题关联。每条关系须提供基于正文内容的 reason，不能仅因目录相邻就自动连边。关系与章节归属不同，也不改变正文的审核状态。没有连线不表示条目之间没有其他关系。

维护关系时使用永久标签，不使用会随正文重排而变化的章节编号。预设路径的 nodes 按阅读顺序填写，每对相邻节点必须有同方向的显式 prerequisite 关系。数据中的 nodes 只存条目；root 表示知识库总节点，chapters 提供章节元数据，sections 提供专题元数据及所属章节。构建时核验条目节点与永久登记表一一对应、专题清单完整及各级归属一致，拒绝悬空关系、自环、重复关系、先学关系环和缺少对应连边的路径。新增正文会自动进入条目节点清单；编者再按实际内容补充有依据的关系。

知识树页面通过独立的本地 CSS 和 JavaScript 模块加载。knowledge-3d-layout.mjs 计算三维层级布局，knowledge-3d.mjs 负责 WebGL 视图，knowledge-3d.css 只在知识树页面加载。构建时为知识树导入的核心、三维布局和渲染模块加入内容校验值，并用改写后的主模块内容生成缓存版本。章节归属、建议先学箭头与无向主题关联的含义在两种视图中保持一致。

Three.js 0.186.1 作为静态依赖收录在 site/assets/vendor/three/，浏览器从本站加载，不依赖外部 CDN。其 MIT 许可证和官方 npm 包的版本、来源、完整性及文件校验值随站点提供：许可证、来源记录。升级依赖时须同时更新文件与来源记录，保留许可证；应使用新的版本目录并同步渲染模块的导入路径，避免浏览器混用新主模块与缓存中的旧 three.core.js。该依赖许可不改变知识正文的许可。

WebGL 不可用或三维渲染初始化失败时，页面提供明确提示及学习流程图入口；关闭 JavaScript 后仍可进入完整目录。章节目录、主导航和首页均提供入口。构建与静态链接检查沿用上面的普通修改命令，生成的关系数据也可从“版本与来源”页面下载核对。修改知识树后运行：

node --test tests/knowledge.test.mjs tests/knowledge-3d.test.mjs

逐条内容结构检查运行 .venv/bin/python tests/tag_depth_coverage.py，核对全部永久条目与标题、展开的小节及来源索引。该检查单独报告独立审核是否待完成；如需把完整版本审核记录作为必需条件，使用 --require-review。数值复算脚本 tests/tag_depth_*_checks.py 和 tests/tag_depth_*_independent.py 可从新检出的仓库运行，报告写入本地 .build/tag-depth/，不修改审核清单。

自动检查之外，还应在浏览器核对三维旋转、节点选择、逐级展开与折叠、流程视图切换及手机触摸操作。

公式与引用

支持行内 LaTeX $x^2+y^2$ 和独立行公式 $$...$$。示例：

\[ \omega_c=\frac{|q|B}{m}. \]

这只是数学排版示例。技术正文仍需注明物理假设、符号、单位和原始来源。

每个专题和条目都提供永久链接、GitHub 源文编辑入口和 BibTeX 引用。参考文献沿用 来源索引，原始核对日期不会在发布时自动更新。

发布到 GitHub Pages

本地构建后发布预生成的 docs/，由 GitHub Pages 原生流程提供网站。没有定时任务，也不需要服务端数据库。

先提交正文及构建代码，再运行：

.venv/bin/python scripts/publish.py

发布脚本要求干净的 main 分支，先快进同步，重建、检查全部内部链接后更新 docs/，使用普通提交和推送。发布回执 edition.json 记录实际构建所基于的提交与源文件校验值，随后存储网页的提交可能与它不同。

讨论与评论

已使用 GitHub Discussions。条目的讨论标题包含永久标签，可以从正文进入对应讨论检索或新建页面。

站内嵌入式评论尚未启用；如需 giscus，需先为组织安装并授权该 GitHub App，再配置仓库与分类标识。原生讨论入口无需这个额外应用。

验证范围与许可

自动检查包括源文档覆盖、永久标签、内部页面与片段链接、搜索索引、阅读顺序和发布回执。网页结构检查和公式排版不代表数学证明、物理模型或工程设计已通过审核。内容核验范围单独列在 核验记录。

等离子体教学算例与公式排版可复现检查：

.venv/bin/python tests/physics_checks.py
.venv/bin/python tests/icrh_checks.py
.venv/bin/python scripts/extract_math.py
node scripts/check_math.mjs

先构建 _site，再提取其中的连续正文公式。物理检查验证指定的算例、守恒关系和极限；MathJax 检查只验证公式语法与渲染。site/verification.json 保存复核范围与正文 SHA-256；修改正文后，旧核验记录不能自动成为新版本的审核证据。只有校验值仍匹配的专题会显示模型辅助复核标识，专家审核仍单独管理。

阅读组织参考 Pome。站点生成器和样式为本项目实现；未复制 Pome 的书稿或数学内容。自托管 MathJax 的许可证保存在 vendor/mathjax/LICENSE。知识正文沿用原有许可要求，本仓库不默认授予开源许可。
